# Ledger-service reconciliation drift between TimescaleDB and Postgres

## Symptoms

The ledger-service may experience reconciliation drift between TimescaleDB and Postgres. This manifests as discrepancies in financial reports and audit logs, potentially leading to incorrect financial statements.

## Diagnostic Steps

1. **Verify the Discrepancy**: Check the financial reports generated by the ledger-service against the expected values. Use the `GET /api/v1/reports/transactions` endpoint to pull transaction reports and compare them with the ledger entries in TimescaleDB.

2. **Check TimescaleDB Logs**: Use Loki to review the logs for any anomalies or errors in the ledger-service that might indicate issues during the transaction recording process.

3. **Analyze Kafka Topics**: Ensure that all relevant messages in the `ledger.transactions` Kafka topic have been processed without errors. Use Datadog to check for any consumer lag or missed messages.

4. **Database Comparison**: Run a SQL query to compare the entries in TimescaleDB with those in Postgres. Look for mismatched or missing entries.

5. **Review Recent Deploys**: Check ArgoCD for any recent changes or deployments that might have affected the ledger-service's data processing logic.

## Mitigation

1. **Reprocess Missing Transactions**: Identify and reprocess any missing transactions by replaying the relevant Kafka messages. Ensure that the ledger-service correctly updates both TimescaleDB and Postgres.

2. **Correct Data Discrepancies**: Manually correct any discrepancies found between TimescaleDB and Postgres. This may involve direct database updates or using service APIs to ensure consistency.

3. **Patch the Service**: If a code issue is identified as the root cause, deploy a patch to the ledger-service to prevent future occurrences. Use ArgoCD to manage and deploy the fix.

4. **Implement Monitoring**: Set up additional Datadog alerts to monitor for reconciliation drift indicators, such as unexpected spikes in transaction discrepancies.

## Verification

- Confirm that the financial reports now match the expected values. Use the `GET /api/v1/reports/transactions` endpoint to verify that the data in TimescaleDB and Postgres is consistent.
- Ensure that all Kafka messages in the `ledger.transactions` topic have been processed without errors.
- Check Datadog for any lingering alerts related to the ledger-service.

## Escalation

If the issue is not resolved within 60 minutes, escalate to `pagerduty-sigma` for further investigation and support. Provide all diagnostic data collected during the initial investigation.
